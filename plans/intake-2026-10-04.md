## 4. Bugs

**C1. Changing or deleting a mapping orphans the reminders it created.** Reminders are matched to mappings by value: name (the address), trigger and radius (`app.py:431-437` for deletion, `:453-461` for the dedupe). Nothing stores which reminder came from which mapping. Reproduced in a scratch run against 40fab8a: a mapping whose address was edited from OLD to NEW, a task still carrying the label and holding the OLD reminder. The webhook added a NEW reminder and deleted nothing; then, with the label removed from the task, it again deleted nothing. The OLD reminder matches no mapping, so no later event can remove it. The same happens to every reminder of a mapping that is deleted. Deleting was always like this; Phase 5 made editing a one-step action, which makes the path easy to walk. The fix plan's interview described the edit as "the old reminder on existing tasks is not rewritten until the task's labels next change". That was wrong: it is never rewritten. Effect for the user: a location alert at the old address on every task that was tagged before the change, until each is removed by hand in Todoist. Fix sketch: when a mapping is edited or deleted, fetch reminders once, select those matching the mapping's old (name, trigger, radius), and send one sync batch that deletes them and, for an edit, re-adds each on the same item with the new values. About 25 lines and two tests. The alternative, a table recording reminder IDs per mapping, is more schema for the same result. Effort S to M. Confidence HIGH.

**C2. Retries can outlast gunicorn's worker timeout.** Introduced in Phase 4. Measured against a threaded stub: a read timeout is retried, 4 attempts for GET and 4 for POST. With the production timeouts (`app.py:127` 10 s, `:171` 15 s) and 6 s of backoff, one call can take 46 s (labels) or 66 s (sync). The webhook makes both in sequence (`:391-392`). Gunicorn's defaults, read from the installed package, are one sync worker and a 30 s timeout. Scenario: Todoist accepts connections and then stalls; the first webhook holds the only worker until gunicorn kills it at 30 s, the health check fails meanwhile, and page loads hang. Todoist redelivers 15 minutes later, so nothing is lost; the cost is the app being unresponsive in 30 s slices for as long as the stall lasts. Before Phase 4 a stalled call cost at most 10 s plus 15 s, under the limit. Fix: `read=0` on the `Retry` (retry status codes and connection failures, not stalls) and a 10 s sync timeout, which bounds a stalled webhook at 20 s. Effort S. Confidence HIGH on the mechanics; never observed.

**C3. A non-ASCII signature header returns 500, not 401.** Introduced in Phase 2. `hmac.compare_digest` refuses `str` arguments containing non-ASCII characters; `app.py:121` passes the header as received. `webhook_signature_ok(b"x", "\xe9")` raises `TypeError: comparing strings with non-ASCII characters is not supported`. It fails closed, nothing is processed, but any caller can produce a traceback in the log at will. Fix: compare bytes, `hmac.compare_digest(expected.encode(), header.encode("latin-1", "replace"))`. Effort S. Confidence HIGH.

**C4. Every reminder add or delete downloads the whole account.** Present before this plan. `todoist_sync` defaults `resource_types` to `["all"]` with `sync_token="*"` (`app.py:166-169`), and the two command callers pass no resource types (`:198`, `:214`). So each `reminder_add` and `reminder_delete` also asks Todoist for a full sync of every task, project and label, then discards it. It costs time on the one worker and memory on a 256 MB machine, in proportion to the size of the account. Fix: `resource_types or []`. Effort S. Confidence HIGH that the full sync is requested; that an empty list is accepted is from the protocol documentation, untested.

Low:

Unverified; it needs one look at a real delivery from a shared project.

## 6. Opinions

- **mypy is close to a formality here.** One of 18 functions in `app.py` is annotated, and without `check_untyped_defs` mypy does not look inside the other 17. Turning it on yields a single error (`app.py:245`, the `kwargs` dict's inferred value type). Fix that line and set the flag, and the gate checks the whole file.
- `session["oauth_secret_state"]` is never removed after a successful login (`app.py:253, 269`). Harmless, since the code is single-use; `session.pop` would be tidier.
- The redirect URI sent in the token exchange is still `/authorize`, not the callback (`app.py:282`). It works; it still reads like a bug.
- CI deploys on every merge to master, including a documentation-only one. A `paths-ignore` for `plans/**` and `*.md` would save a machine restart per report.
- `uv:latest` in the Dockerfile and `superfly/flyctl-actions/setup-flyctl@master` in CI are unpinned.
- Bootstrap 4.0.0-beta.2 remains.
