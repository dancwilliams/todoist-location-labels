**H1. A second label can take the key of a half-applied edit, and its sweep then moves reminders that belong to the first label.** The same-key refusal (`app.py:520-526`) compares the new key against the keys stored in the database. After an edit of mapping A, Home→Oak, whose second request was dropped (502, A kept at Home, `:536-540`), tasks 900 and 901 hold Oak reminders that match no stored row. A second label B submitted at Oak is accepted (302, no 400) because A's row says Home. A's stray reminders now match B by value, so an edit of B to a third place sweeps them: tasks 900 and 901, which carry label A only, end holding B's reminder beside A's Home one (final state `[900 Elm, 900 Home, 901 Elm, 901 Home, 902 Home]`). This breaks the sentence at `CLAUDE.md:76` that no two mappings' reminders can share a key, by way of the dropped request. The reminder clears on each task's next change (the webhook deletes a reminder whose mapping is not on the task, `:613-628`). Reproduced through app paths: `scratchpad/improve/test_edges.py::test_another_mapping_takes_the_half_applied_key` (passes, rerun here). Pre-existing: the key check (#43) and the half-applied state predate #53. Needs a dropped request, then a *different* change at the half-applied place instead of the resubmit the page asks for; a cousin of F3 (`README.md:16`, "Submitting a different change instead leaves the reminders the first one made at a place no label maps"), except that here a label does come to map that place. **Fix (S, Dan's call):** the README clause for F3 extended ("… or that a label mapped there later will treat as its own"), or the key check also reading Todoist for reminders at the new key before accepting (one `todoist_get_reminders` call, M). ## 6. Opinions

1. **The table's 502 check is blind for a third of its rows.** `tests/test_routes.py:510` asserts `.name == "Home"` to show the mapping was not moved; the `coordinates only` target (`HOME_MOVED`, `:367`) keeps the name "Home", so a regression that committed `lat = 9.0` before raising would pass the check (reproduced with a simulated regression: `test_edges.py::test_table_502_assertion_cannot_see_a_moved_row_on_coordinates_only`, `row.lat == 9.0` with `.name == "Home"`).
