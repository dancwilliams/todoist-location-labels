## 4. Bugs

**B5. A refused or status-less delete in an edit sweep leaves the other tasks moved under a mapping that stayed, and the resubmit the 502 asks for gives those tasks two reminders.** `todoist_run_commands` now sends every batch and reports every refusal at the end (`app.py:256-266`), and `sweep_reminders` re-raises unless every refused uuid is an add (`:324-326`); the route then keeps the old place and answers `SWEEP_FAILED`, "Submit the same change again" (`:492-496`). By then every other delete and add has been applied: N−1 tasks sit at the new place under a mapping that says the old one, and the task whose delete was refused has both. A webhook for any moved task finds nothing at the mapping's place and adds one there (`:587-606`). The resubmit sweeps every old-place reminder and re-adds at the new place without looking at what the task already has (`:317-320`), so each such task ends with two identical reminders — the refused-delete task even without a webhook in between. Reproduced with a stateful stub (`scratchpad/probe_sweep.py`, rerun here), tasks 900 and 901 at Home, edit to Oak, 900's delete refused:

```
edit -> 502        mapping='Home'  reminders={'900': ['Home', 'Oak'], '901': ['Oak']}
webhook 901 -> 200 mapping='Home'  reminders={'900': ['Home', 'Oak'], '901': ['Oak', 'Home']}
resubmit -> 302    mapping='Oak'   reminders={'900': ['Oak', 'Oak'], '901': ['Oak', 'Oak']}
```

A delete that was applied but came back with no status (`:263-264` counts it as refused) gives `'901': ['Oak', 'Oak']` the same way. Before #46 a refusal in batch k stopped batches k+1 onward; now every batch is sent, so the exposure is every task but one. This is B1's mirror: #46 saved the mapping when only adds were refused, for exactly the reason stated in its comment (`:327-331`), and left the refused-delete case keeping the mapping because "a reminder is still at the old place" — true, and not enough, because N−1 are at the new one. Trigger never observed: `reminder_delete` answers `ok` even for an unknown id (PR #46), so the remaining candidates are a transient per-command error and a missing status. **Fix (S), at the root rather than per case:** `sweep_reminders` already holds every reminder (`located`, `:313`); skip the re-add for a task that already has a reminder at `new_place`. Then a resubmit is idempotent in every mixed state — refused delete, missing status, a worker killed mid-sweep by a deploy's SIGINT (opinion 4) — and the mapping rule can stay as it is. Traced against the stub above: resubmit deletes 900's and 901's Home reminders, skips both re-adds, result `{'900': ['Oak'], '901': ['Oak']}`. Test through `fake_todoist` with a reminder pre-seeded at the new place: the edit sends one delete and no add. Confidence HIGH on the mechanism; LOW on frequency.

**B6. The shapes that raise `AttributeError` still give a 500 instead of the 502 sentence.** #47 widened the two routes to `(RequestException, KeyError, TypeError)` (`app.py:438`, `:492`). A reminders page whose `results` items are not dicts raises `AttributeError` in `reminder_is_at` (`:297`, `reminder.get`); a sync answer that is not a dict, or a `sync_status` that is not a dict, raises it in `todoist_run_commands` (`:259`, `:263`). Three probes on `POST /delete_label_location/1` (`probe_items.py`: `{"results": ["x"]}`; `probe_shape.py`: sync answer `[]`, then `{"sync_status": []}`) each printed `AttributeError … has no attribute 'get'` and `500`. The mapping is kept in every case. In the sync-answer cases the batch has already been applied and later batches are skipped, which is B5's mixed state with a bare 500 instead of the resubmit sentence. Never observed. **Fix (S), at the root:** `todoist_get_all` checks the page is a dict with a list of dicts, and `todoist_run_commands` checks the answer and `sync_status` are dicts, each raising `RequestException` on anything else; the three catch tuples (`:353`, `:438`, `:492`, and the webhook's `:543`) then shrink to `RequestException`, and the CLAUDE.md clause becomes true for every shape. Confidence HIGH.

## 6. Opinions

1. **No traceback on a swallowed `KeyError`/`TypeError`.** `app.py:439` and `:493` log `%s` of the exception with no `exc_info`, so a future bug inside the sweep's read reads as `Could not remove reminders, mapping 5 kept: 'id'` and tells the user to retry forever. Nothing is lost; it is hard to diagnose from a 100-line log. `exc_info=True` on those two lines, or B6's fix, which makes the tuple a single `RequestException` again.
2. **The fake Todoist is stateless** (`tests/conftest.py:133-163`: `do_GET` answers `state["reminders"]` whatever was posted). `test_refused_delete_during_edit_keeps_the_mapping` (`tests/test_routes.py:295-302`) is B5's setup and asserts only the 502 and `name == "Home"`; it cannot see the Oak reminder created alongside. B5's fix can be tested statelessly (pre-seed the new-place reminder); the interleaving itself needs the fake to apply commands to its reminder list. M; worth it only if sweeps keep changing.
3. **`test_a_repeated_cursor_raises`** asserts `len(calls) <= 3` where the code makes exactly 2 GETs (`app.py:168-179`: the cursor goes into `seen` after page 1 and is found on page 2); an a, b, a cursor raises on GET 3 and is untested. Pin `== 2`.
4. **SIGINT is gunicorn's quick shutdown.** Fly's default `kill_signal` (now implicit, `fly.toml`) is SIGINT, which gunicorn treats as quick stop, not graceful; a sweep running when a deploy lands is cut off mid-request, leaving B5's mixed state. Deploys land on every merge, docs-only ones included (carried). The window is seconds per deploy and B5's fix makes the resubmit safe; `kill_signal = "SIGTERM"` would be the alternative and would reverse half of #47's `fly.toml` trim.
5. **Request lines carry no status code** (`app.py:89`), so the log cannot answer "how many 502s today". A status needs an `after_request` hook; the 100-line buffer limits what any such line is worth.
6. Carried: error pages are Flask's bare page and the form is lost (ruled out of scope in the third plan); the radius prints as "100.0 M" (`templates/index.html:159`, `Float` column); `from urllib3.util.retry import Retry` imports a transitive dependency; `session["oauth_secret_state"]` is never removed (`app.py:366`); the token exchange sends `/authorize` as its redirect URI (`:395`); `uv:latest` (`Dockerfile:3`) and `setup-flyctl@master` (`ci.yml:40`) are unpinned; Bootstrap 4.0.0-beta.2.
