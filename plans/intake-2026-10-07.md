## 4. Bugs

**G1. `uv run python app.py initdb` crashes before creating anything.** `app.py:656-658`: under `if __name__ == "__main__"`, the `initdb` branch calls `db.create_all()` with no `app.app_context()`. Flask-SQLAlchemy 3 resolves the engine through `current_app` (`flask_sqlalchemy/extension.py:687` in the installed 3.1.1), so the call raises `RuntimeError: Working outside of application context` and exits 1 with a traceback; no table is created. Reproduced: `DATABASE_URL=sqlite:///<scratch>/initdb.db` plus dummy `TODOIST_*`/`GOOGLE_MAP_API_KEY` values, `uv run --no-sync python app.py initdb` → exit 1, the file holds no `location_label` table. The same `create_all` inside `with app.app_context():` (run from a scratch script, the repo untouched) creates `user` and `location_label` with `CONSTRAINT uq_location_label_user_label UNIQUE (user_id, label_id)`, which is what `CLAUDE.md:91` relies on for a fresh database. History: the import-time `with app.app_context(): db.create_all()` that once made the command work as a side effect was commented out in f4bd48c (2023-04-06) and the comment deleted in #35 (83125ce); the `__main__` branch itself is from the 2017 original and never entered a context; Flask-SQLAlchemy has been pinned at 3.1.1 since 0e08269 (2026-03-20), and the version installed between 2023 and then is unrecorded (`requirements.txt` was unpinned). **Cost:** the README's local setup (`README.md:49-52`) fails at its third step; a fresh database for disaster recovery or a second environment has no working documented path (`CLAUDE.md:91`); the one block of `app.py` no test touches (`:657-660`) is the one that is broken. **Fix (S):** `with app.app_context(): db.create_all()` at `:658`, plus a test that fails first: run the block against a scratch SQLite (a subprocess with `DATABASE_URL` set, or `runpy` with `sys.argv` patched) and assert `location_label` exists with the unique constraint. Confidence HIGH; pre-existing; not introduced by any fix plan.
